# ADR-0075 — The toolchain on Oxc: oxlint, the project's Rust linter, oxfmt and TypeScript 7

**Status**: Accepted (2026-10-17, decided by the Product Owner at F19's refinement and at the review of the ADRs, EN-094; recorded by EN-085). Supersedes ADR-0009, ADR-0010 and ADR-0013. ADR-0071 stands.

## Context

- ADR-0009 chose the toolchain: TypeScript 6, Vite, Vitest, ESLint, Prettier and VitePress, every package a development one, pinned, justified and audited. ADR-0010 made ESLint carry every rule it could check before TypeScript. ADR-0013 set Prettier beside ESLint, not inside it.
- E17 asked for tooling as fast as it can be, for the agent (ADR-0069), every tool of the project's own in Rust (ADR-0073). F19 moved each check to a native tool: TypeScript 7 for the type check (EN-071), the API pages from a Rust generator instead of TypeDoc (EN-072), oxfmt instead of Prettier (EN-073), oxlint with its native and type-aware rules (EN-074), and the rules oxlint lacks rewritten in a linter of the project on Oxc's crates (EN-075 to EN-084, EN-095), until ESLint ran no rule ([research note 0023](../research/notes/0023-f19-oxc-and-rust-tools.md)).
- Measured on this tree (2026-10-17): ESLint alone 14.2 s, against 1.5 s for oxlint with the type check and 0.24 s for the project's linter on 2,048 files; Prettier 12.4 s against 0.4 s for oxfmt; `check:all` on a code story about 39 s once ESLint left, against 70 to 90 s aimed at (EN-085).
- At the review of the ADRs, the Product Owner decided that one ADR on the Oxc toolchain replaces 0009, 0010 and 0013: the toolchain changes, the rules on dependencies stay, and "the linter first" stays, the linter being oxlint and the project's Rust linter (EN-094).

## Decision

1. **The toolchain.** TypeScript 7 is the only TypeScript (`typescript` 7.0.2): its compiler runs under oxlint's `--type-check` and as `npm run typecheck`. Vite, Vitest and VitePress stay, VitePress on 2.0 alpha for the reason ADR-0009 gave (1.6 bundles a vulnerable Vite 5). The formatter is oxfmt, run by `tools/format`; the linters are oxlint, with `oxlint-tsgolint` for the rules that need types, then the project's linter `tools/lint`; the API pages come from `tools/api-pages` and the declarations from `tools/declarations` (ADR-0071). ESLint, typescript-eslint, every ESLint plugin, Prettier, TypeScript 6 and TypeDoc are removed.
2. **The rules on dependencies stay** (from ADR-0009): development packages only, `dependencies` empty; each pinned to an exact version and justified by its row in `docs/tooling/dependencies.md`, which a test holds; `npm audit` at any severity in `check` and before `build`; each on its latest version at least 7 days old (`deps:outdated`), TypeScript no longer held to patches; an override only against an advisory, checked at each retrospective; a crate of the Rust tools under the same rules (ADR-0073).
3. **The linter first** (from ADR-0010), the linter being oxlint and the project's Rust linter:
   - a rule a linter can check lives in a linter, even when a `tsconfig.json` option exists: `noUnusedLocals`, `noUnusedParameters` and `noFallthroughCasesInSwitch` stay off, for oxlint's `no-unused-vars`, `no-fallthrough` and `no-unreachable`; `tsconfig.json` keeps only what no linter can guarantee (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`…);
   - every rule is an error, none a warning, and oxlint runs with `--deny-warnings`;
   - every rule is decided once: `.oxlintrc.json` names each rule it runs and only rules oxlint has (`tests/oxlint-config.test.ts`); each rule of the project's linter is a file of `tools/lint/src/rules/` with its tests;
   - a one-off exception is a directive with its justification after `--` — `// oxlint-disable-next-line rule -- why` for oxlint, `// lint-disable-next-line rule -- why` for the project's linter — listed in the register of exceptions (ADR-0066); a directive that turns off nothing is reported.
4. **The formatter beside the linters** (from ADR-0013): oxfmt lays out every file kind, Markdown included, with tables without padding (ADR-0068); the linters add what it does not decide — blank lines between statements, comment style, JSDoc layout — and oxfmt sorts the imports (`sortImports`). One command fixes everything: `npm run fix` runs the formatter, then oxlint `--fix`, then the project's linter `--fix`.
5. **The scopes by path** that ESLint's `eslint/scopes/` held are oxlint's `overrides` in `.oxlintrc.json` and the `SCOPES` of `tools/lint/src/scopes.rs`. ADR-0014's relaxation of the functional rules in the DOM layers (`src/render/`, `src/interaction/`, `playground/`), centralized in `eslint/scopes/dom-layers.ts`, is now the scope `dom-layers` of `tools/lint/src/scopes.rs`.
6. **A Rust plugin API for oxlint is watched**: oxlint takes outside rules only as JavaScript plugins today, so the project's rules run in their own linter on Oxc's crates; if oxlint offers a way to plug rules written in Rust, they move into it and the separate linter goes. Checked at each epic's tooling pass ([improvement log](../process/improvements.md), 2026-10-17).

## Reasons

| Option | For | Against |
| --- | --- | --- |
| oxlint, the project's Rust linter and oxfmt (chosen) | native tools: lint and format in about 2 s instead of 27 s; every rule kept, rewritten or dropped with its reason; one language, Rust, for the project's own rules (ADR-0073) | a linter of the project to maintain; a rule oxlint lacks costs a rewrite |
| ESLint kept for the rules oxlint lacks | no rewrite | ESLint's 14 s and TypeScript 6's API for a handful of rules; two linters on every file |
| The project's rules as oxlint JavaScript plugins | inside oxlint, one command | JavaScript run on every file, against the Rust rule (decided 2026-10-17, note 0023) |

## Consequences

- `npm run lint` runs oxlint, then the project's linter, on the same targets; `lint-staged` and `npm run fix` do the same; nothing calls ESLint nor Prettier (`tests/oxlint-config.test.ts`, `tests/check-targets.test.ts`).
- `check:all` builds the documentation site and the playground only when `docs/`, `src/`, the playground or their build changed against the branch's base (EN-085).
- `.claude/rules/tooling.md` states that TypeScript 7 is the only TypeScript, TypeScript 6 and TypeDoc are removed and the API pages come from the Rust generator.
- The editors use Oxc's extension (`oxc.oxc-vscode`); `.vscode/settings.json` no longer points VS Code at `node_modules/typescript/lib`, where TypeScript 7's package holds no `tsserver.js` to load.
- F21 rewrites in Rust the TypeScript tools that remain around the library (ADR-0073).
