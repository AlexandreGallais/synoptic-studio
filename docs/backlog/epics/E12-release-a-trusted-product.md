# E12 — Release a product people can trust

| Field                       | Content                                                                                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| For                         | teams drawing synoptic views, and the people deciding whether to adopt the tools                                                                              |
| who                         | need to trust a tool before using it in their work                                                                                                            |
| the solution                | published library and editors, with summary documentation, user manuals and regression tests                                                                  |
| is a                        | release of the whole project                                                                                                                                  |
| that                        | can be installed, understood and evaluated without reading every page                                                                                         |
| unlike                      | a repository that only its authors understand                                                                                                                 |
| our solution                | every behavior sourced and tested, summarized in a few documents written for humans                                                                           |
| Business outcomes           | the library is published (ESM with types, runs in any JavaScript engine); each editor has a user manual; an overview explains the project in a few pages      |
| Leading indicators          | a newcomer installs and uses the library from the overview alone; regression and end-to-end suites pass on each release                                       |
| Non-functional requirements | documentation complete but not excessive; summaries link to the detailed pages; no runtime dependency                                                         |
| In scope                    | project overview, architecture summary, user manuals, getting-started guide, npm publication, regression and end-to-end tests, size budget, public API report |
| Out of scope                | hosting a service; features not specified in the other epics                                                                                                  |
| Closure criteria            | the Product Owner and one person new to the project understand and use the release from the summary documents                                                 |
