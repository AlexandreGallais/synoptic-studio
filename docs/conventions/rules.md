# Every rule and why

The record of EN-093 (2026-10-17): the rules, formatter settings, checks, hooks and conventions this repository runs, each with what it guards and its verdict (kept, changed, dropped or added), and the evidence behind it. Each was judged by the test of [lint](./lint.md#principles): a rule stays if it serves the one who writes and reads this code, and goes if it only costs time on what is already respected. Read this page to change a rule, not to apply one.

## Result

| What | Reviewed | Kept | Changed | Dropped | Added |
| --- | --- | --- | --- | --- | --- |
| oxlint's rules | 364 run, 507 not run | 362 | 2 (`jsdoc/require-param` and `require-returns` off in test files) | 0 | 9 correctness rules no triage had decided, 11 of Vitest's in test files |
| the project's linter (`tools/lint`) | 236 | 236 | 1 (`unicorn/comment-content` keeps `applications`) | 0 | 0 |
| the formatter's settings (`.oxfmtrc.json`, `.editorconfig`, the table pass) | 13 | 13 | 0 | 0 | 0 |
| checks, hooks, conventions, scripts | 23 | 19 | 2 (the story skill's per-task check, the `eslint` scope dropped) | 1 (`lint:fix`) | 1 proposed to F21 (the story id in each commit's footer) |

The rules are kept almost whole because the evidence says they cost little and guard much:

- **Speed**: oxlint runs in 1.1 s with its type-aware rules, the project's linter in 0.4 s over 2,051 files and pages (this Mac, 2026-10-17). The 9 rules added changed neither: 1.07 to 1.28 s before and after, over three runs each.
- **Exceptions**: 29 directives in the TypeScript of the tree ([register](./exceptions.md)), 26 of them one rule pair (`consistent-type-assertions` with `no-unsafe-type-assertion`) on browser APIs the DOM types lack. A rule that only costs time would show as directives; none does.
- **Friction**: the findings the agent met in its own transcripts since E01, counted by rule (ESLint's report format, `records/transcripts`): `local/kind-limits` 340, `jsdoc/informative-docs` 310, `local/folder-layout` 266, `unicorn/max-nested-calls` 242, `complexity` 232, `no-magic-numbers` 208, `@typescript-eslint/naming-convention` 149, `local/kind-naming` 130, `func-style` 100. Each was read again below: each finding is a function split, a description made to say more than its name, a calculation named, a name made searchable. These are the rules' work, not their cost. Since EN-107 the **Findings** section of `npm run metrics` makes this count at each report, per epic, the hooks' refusals and the type, Clippy and `check:all` findings with it ([metrics](../tooling/metrics.md#findings)): the next review of the rules reads it there. Its first count, on 2026-10-18 over the 1.6 GB of transcripts this Mac keeps, is lower than the one above, made by hand from `records/transcripts`, but ranks the same rules first: `local/kind-limits` 250, `jsdoc/informative-docs` 222, `@typescript-eslint/no-magic-numbers` 219, `@typescript-eslint/no-unsafe-call` 216, `@typescript-eslint/naming-convention` 208, `unicorn/max-nested-calls` 207, `complexity` 189, `local/folder-layout` 144; the refusal most met, `guard-bash`'s chained Git command in a worktree, 73.

## Rules added

oxlint's correctness rules that no ESLint plugin had were never decided by the triage of EN-074, which started from ESLint's rules: its `correctness` category is off and each rule is named. EN-093 read the 51 left off and the 12 `suspicious` ones, and turned on those that report wrong code the compiler and the project's linter both let through. None reported on the tree; each has a planted case in `tests/oxlint-rules-reviewed.test.ts`.

| Rule | Reports | Why it serves |
| --- | --- | --- |
| `oxc/bad-comparison-sequence` | `a === b === flag`, `a < b < c` | the case `unicorn/no-chained-comparison`'s drop left unreported; no Rust rule needed |
| `oxc/bad-match-all-arg` | `matchAll` with a pattern without `g`, a `TypeError` at run time | the compiler does not see the flag |
| `oxc/bad-replace-all-arg` | `replaceAll` with a pattern without `g`, the same | the same |
| `oxc/bad-min-max-func` | `Math.min(Math.max(n, 10), 0)`, always the same value | a clamp written backwards, a geometry bug |
| `oxc/const-comparisons` | `n > 5 && n < 3`, always false | ranges are the library's daily work |
| `oxc/missing-throw` | `new Error("x");` without `throw` | an error never raised |
| `oxc/number-arg-out-of-range` | `n.toString(40)` | a radix or precision out of range |
| `oxc/only-used-in-recursion` | a parameter only passed to the recursive call | a dead parameter in a recursive fold |
| `unicorn/no-length-as-slice-end` | `xs.slice(0, xs.length)` | dead code |

oxlint's `vitest` plugin was off: nothing stopped a test left focused (`it.only`) from hiding the rest of the suite, since Vitest refuses `.only` on a CI only, and `check:all` runs locally. Its correctness rules that report nothing on the tree are on in test files, each with a planted test in the same file:

| Rule | Reports |
| --- | --- |
| `vitest/no-focused-tests`, `vitest/no-disabled-tests` | a test left focused or skipped |
| `vitest/no-identical-title`, `vitest/valid-title` | two tests under one name, an empty title |

| `vitest/valid-expect-in-promise`, `vitest/require-awaited-expect-poll` | an assertion in a promise nobody waits for |
| `vitest/valid-describe-callback`, `vitest/no-duplicate-hooks`, `vitest/hoisted-apis-on-top` | a group without its function, a hook declared twice, a module mock where it is not hoisted |

## Function limits (ADR-0011), measured

| --- | --- | --- | --- | --- | --- |
| `math` | 91 | 1, 2, 4 % | 2 % | 3, 8, 4 % | 3 % |
| `geometry` | 87 | 1, 4, 3 % | 0 % | 7, 13, 0 % | 2 % |
| `domain` | 187 | 2, 3, 3 % | 0 % | 6, 13, 2 % | 0 % |

| `procedure` | 375 | 2, 3, 27 % | 38 % | 8, 17, 0 % | 2 % |

**Kept as they are.** 233 functions (26 %) sit on one limit, almost all of them procedures at complexity 3 or depth 1: the limit that ADR-0011 meant to bind — a procedure may be long but not branched — binds, and the others leave room (no procedure near 40 lines: its longest is 37, the 90th percentile 17). The 340 findings of the transcripts are the splits it asked for. Raising a limit would let branching back into procedures; lowering one would split functions that read well.

The test of a limit is the split it forces ([one business context per function](./functions.md#one-business-context-per-function)): two halves with invented names of a context that cannot be divided would show a limit to reshape. None was found. Of the 611 exported functions of `src/` and `playground/`, 265 are called from one place only, the functions a split makes; a sample of 45 of them, one in six, each names a context of its field — `edgeLengths`, `cubicVelocity`, `hslComponent`, `parseNameRecords`, `firstBaselineOffset`, `stretchedRightHalf` (the right half of a stretched polygon, a step of its derivation) — and no file of the 793 is named as a part (`-a`, `-b`, `-part`, `-rest`, `-helper`, `-inner`). `unicorn/max-nested-calls` (3 calls deep at most, 242 findings) is the same guardrail for formulas: `round(scale(add(a, b), k))` passes, a fourth level is a step that deserves its name.

## Consistency or ceremony

Every group of rules sits on one side of one question: does it make the code always the same shape, so that it is written and read without a choice, or does it only add writing that changes neither how fast nor how surely the work goes?

| Side | Groups | Verdict |
| --- | --- | --- |
| consistency: one shape, written by a fix or checked in under a second | the formatter's layout, blank lines (`padding-line-between-statements`), import order and members, `func-style`, early returns and no `else` after a return, `prefer-ternary`, one form for types (`type`, `T[]`, property signatures), JSDoc layout and tag order, names by role and boolean prefixes, kebab-case files, one export per file, barrels and canonical paths | kept: the agent never chooses between two forms, and a diff holds only what changed |
| correctness: a bug the compiler lets through | promises, `no-unsafe-*`, strict booleans, exhaustive `switch`, regular expressions, the added `oxc/` rules, Unicorn's misuse rules | kept |
| the method's rules | `@kind` and its limits, `@see` to a read source, no magic number, the functional core | kept: they carry ADR-0011, ADR-0014, ADR-0049 and the rule that every calculation cites a verified source |
| ceremony | `@param` and `@returns` on a test file's helpers: 873 tag lines in the test files, restating a typed signature that sits under them, for a function read only by the test beside it | **changed**: off in `*.test.ts`; the description block stays required (it says what the helper builds), and a tag written stays checked (`check-param-names`) |
| ceremony | `npm run check` after each task, then `check:all` at the push: the suite twice | **changed**: the fix and the touched tests at each task, the whole suite once at the push |
| ceremony | `lint:fix`, a second name for `fix` without the formatter | **dropped** |

### `let`, classes and `enum`

| Construct | Here | Why |
| --- | --- | --- |
| `let` | banned everywhere (`functional/no-let`) | in the core, ADR-0014; outside it, `const` alone means every name holds one value, read once; the ban cost 12 findings in all the transcripts, and the shell writes its loops with `const` and its state in the page's modules. Allowing `let` outside the core would need `prefer-const` back to keep it rare, for no case met: kept banned |
| classes | banned (`functional/no-classes`) | the model is plain data (ADR-0025), functions over it are named one per file; a class would tie data to methods the API pages and the barrels do not expect |
| `enum` | banned (`no-restricted-syntax`) | a union of string literals says the same, is erased at compile time, and Node.js runs the hooks and scripts by type stripping, which cannot run an `enum` |

A project of another kind may want them: the [rule catalogue](./rule-catalogue.md) puts each of these rules under the contexts where it serves.
