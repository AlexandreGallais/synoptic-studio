# Library and playground pitfalls

- Importing from another folder = importing **the folder** (`../geometry`); `npm run fix` corrects the path and updates the folder's `index.ts`.
- A new module goes into the folder of its business domain (ADR-0043): never beside folders, and a new domain gets its folder with its first module (`local/folder-layout`).
- A new layer (`src/<layer>/`) exists only with a first module and its `index.ts`, re-exported by `src/index.ts`.
- Barrels: the autofix writes `export type *` for a folder holding only types and never switches back to `export *` once it holds values; `barrels.test.ts` then fails — replace the line by `export *`.
- `noUncheckedIndexedAccess`: an index read is `T | undefined`; an unreachable fallback branch breaks the 100 % coverage. Prefer an explicit, testable fallback (see `cyclicItem`).
- Module constants: `UPPER_CASE` and documented; type members documented too (the API pages' generator, `tools/api-pages`, fails otherwise).
- JSDoc description = sentences; `@param` / `@returns` = fragments without final period. `@kind` is a custom block tag, shown as its own section of an API page (`jsdoc/check-values` off on purpose).
- Procedure verbs and per-kind limits: `tools/lint/src/settings.rs` (verbs added sorted; limits changed only with an ADR).
- Tests: examples with hand-computed values justified in a comment, then properties with `test.prop({ … })` from `@fast-check/vitest` (record form: `max-params` is 3). `toBe` compares with `Object.is`, so `-0` differs from `0`: use `toBeCloseTo` for computed numbers.
- DOM tests start with `// @vitest-environment happy-dom`.
- Run `npm run fix` before each commit, which reports the type errors with the lint (oxlint `--type-check`, EN-091): Vitest strips types, and the unused-imports autofix drops a type import written before the code that uses it (EN-005).
- Zero vectors and signed zeros (ADR-0025): `atan2(+0, −0) = π`, `Math.sign(−0) = −0`, and `toEqual` tells `−0` from `0`. State the intended result for zero-length edges explicitly (see `turningAngle`, `unit`).
- More than three parameters: group them in a named type (`CornerPoints`); tests with many columns use `it.each` over objects.
- Playground visibility: page rules such as `label { display: block }` override the `hidden` attribute; keep the `[hidden] { display: none !important }` rule — a rule by id with `display: grid` or `flex` overrides it too — and test what is displayed (`getComputedStyle`), the page head loaded (US-007, US-031).
- A test refusing a value outside a string union (data read from outside) needs a cast: `// oxlint-disable-next-line @typescript-eslint/consistent-type-assertions, @typescript-eslint/no-unsafe-type-assertion -- <reason>`, on its own line (ESLint reads a trailing one as a comment out of place) (US-009). A complexity limit in a test callback counts `?.` and `??`: destructure with one fallback instead.
- Mutation checks by hand: save the file's content and copy it back; `git checkout` neither restores an untracked file nor keeps uncommitted work in a tracked one (F07).
- happy-dom: `:checked` follows the `checked` attribute, not the state, and the lint autofix wraps selector values in `CSS.escape` (a space becomes `\ `, which happy-dom does not match): find radio buttons by their `checked` and `value` properties (US-010).
- Playground limits (`max-lines` 200, `import-x/max-dependencies` 10, procedure statements 15): split by role into one-export files (`read-shape`, `show-shape`, `show-guided-step`, `write-*`), pass `update` as a callback rather than importing the page's redraw (EN-010).
- `data-*` attributes: the autofix turns `removeAttribute("data-x")` into `delete el.dataset.x`, which the type check refuses (TS4111, `npm run lint`): write `delete el.dataset["x"]` (US-011).
- `expect.closeTo` inside `toMatchObject` / `toEqual` of objects is an `any` for the lint (`no-unsafe-assignment`): assert numbers one by one with `toBeCloseTo` (EN-010).
- Scaling to an integer size: write `o + size · (p − o) / span`, multiplying first — `(29 / 7) · 7` is 29.000000000000004, `29 · 7 / 7` is 29 (F09, `DERIV-free-shape-stretch`).
- A decision kept on a paused feature branch is not on `develop` yet: cite it only from that branch, or say it is paused (F08, 2026-10-11).
- A playground control acting on the shape (button, field) is tested on a **refused** shape too: hide it or guard its handler, or a `NaN` gets stored and crashes later redraws (US-014).
- A playground control that changes one value of a kept free shape (its position, US-018) writes only that value in the stored JSON: `writeStoredFreeShape` also rewrites the width, height and radii fields from the stored shape, undoing what was typed.
- Playground frames and dashes are fills (a ring with `fill-rule: evenodd`, thin rectangles), never a native stroke; skip a frame on a box too small to hold it (US-018).
- A required field added to a model type (ADR-0016, no optional field): the type check (`npm run lint`) lists every literal to complete; in tests, add it where the other fields are written, and let a property draw it (`fc.boolean()`) where the test covers both values (EN-017).
- A bisection in doubles stops shrinking at one unit in the last place, before its nominal step count; a bound it returns may sit on the wrong side of a `>=` by that much: state "within a rounding error", never "at least" (EN-017).
- A clamp before a bisection on a monotone predicate is unobservable (false everywhere ends at the low end, true everywhere at the high end): a mutation survives it; drop it or say so (EN-017).
- The immutability rules read the written code (EN-076): in the core, a parameter or a declared type of the standard library or a package is written `Readonly<DataView>`, never bare; a type of the core needs nothing more, its declaration being checked; `npm run fix` writes what is missing. A module constant holding a function returned by a call has its function type written (`const items: () => readonly Item[] = builtOnce(…)`), or `naming-convention` asks for `UPPER_CASE`.
- happy-dom: a `<select>` moved from a `DOMParser` document loses its `selected` option: choose the value again in the test (US-031).
- Never change the float behavior of a shared math function for a new caller: `npm run golden:check` guards the results of E01 and E14 bit for bit, and a 10⁻¹⁴ drift fails it; add a named function instead (`nonNegativeRemainder` beside `modulo`, EN-038).
- happy-dom keeps the line break right after `<textarea>` that a browser drops: the page's text opens with an empty first line in tests; a test that needs the content types it (US-051).
- A worker never runs `npm run golden:write`: it writes `.git/metrics/golden.json`, shared by every worktree, and would make the check compare against its own branch; only the main thread writes it, before a refactor (F16); it refuses in a worktree (EN-052).
